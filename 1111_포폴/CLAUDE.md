# 안유민 포트폴리오 프로젝트

개인 포트폴리오 웹사이트를 만드는 프로젝트다.
진행 순서: **① 인터뷰 → ② 레퍼런스 조사 → ③ 페이지 제작 → ④ Cloudflare 무료 계정으로 배포**

## 기본 정보
- 본인 정보와 인터뷰 결과는 [`profile.md`](profile.md)에 기록한다. 작업 시작 전에 항상 먼저 읽는다.

## 절대 규칙
1. **사실만 쓴다.** 사용자가 말하지 않은 경력, 수치, 수상, 역할을 지어내거나 부풀리지 않는다.
2. **모르면 묻는다.** 정보가 비어 있거나 애매하면 추측하지 말고 사용자에게 질문한다.
3. 숫자(결과)는 사용자가 직접 확인해 준 값만 쓴다. 대략적인 값이면 "약"을 붙이고 그렇게 표시한다.
4. 문장을 다듬는 것은 괜찮지만, 의미나 사실관계를 바꾸지 않는다.

## ① 인터뷰 규칙
- **한 번에 질문 하나씩만** 한다. 여러 질문을 묶지 않는다.
- 답변을 받을 때마다 `profile.md`에 바로 정리해 저장한다.
- 인터뷰 목표 두 가지:
  1. **강점**과 포트폴리오 페이지에 내세울 **핵심 메시지 한 줄**
  2. **대표 경험 3개**
- 경험마다 아래 4개 항목이 모두 채워질 때까지 묻는다:
  - **문제**: 어떤 상황/과제였나
  - **내 역할과 판단**: 내가 맡은 일, 내가 내린 결정과 그 이유
  - **결과(숫자)**: 참여자 수, 예산, 기간, 조회수, 성과 등 구체적 수치
  - **배운 점**
- 항목이 빈 채로 다음 경험으로 넘어가지 않는다. 숫자가 정말 없으면 사용자에게 확인한 뒤 "수치 없음"으로 표시한다.
- 진행 상황(채워진 항목 / 남은 항목)을 `profile.md`의 체크리스트로 관리한다.

## ② 레퍼런스 조사
- 인터뷰가 끝난 뒤 진행한다.
- 사용자의 분야(MICE·행사 기획, 디자인, 마케팅)와 핵심 메시지에 맞는 포트폴리오 사이트를 조사한다.
- 레퍼런스마다 링크, 참고할 점(레이아웃/색/구성), 왜 맞는지를 `references.md`에 정리하고 사용자와 방향을 정한다.

## ③ 제작
- 정적 사이트(HTML/CSS/JS)로 만든다. 빌드 도구 없이도 배포 가능한 구조를 우선한다.
- 한국어 기본. 영어/일본어 버전은 사용자가 원할 때만 추가한다.
- 모바일에서도 잘 보이게 반응형으로 만든다.
- 사진, 로고 등 이미지가 필요하면 사용자에게 요청한다. 임의 이미지로 경험을 꾸며내지 않는다.

## ④ 배포 (Cloudflare 무료)
- Cloudflare Pages(또는 Workers 정적 자산) 무료 플랜을 사용한다.
- 로그인·계정 생성·결제 정보 입력은 사용자가 직접 한다. Claude는 절차 안내와 명령어 준비를 맡는다.
- 배포 전 사용자에게 최종 확인을 받는다.

## 파일 구조 (예정)
- `CLAUDE.md` — 이 문서
- `profile.md` — 본인 정보 + 인터뷰 결과
- `references.md` — 레퍼런스 조사 결과
- `site/` — 포트폴리오 사이트 소스
